# 投资组合管理器培训项目（中文整理译文）

> 原始项目描述见 [`portfolio_manager.md`](../portfolio_manager.md)。为方便团队执行，
> 本文合并了原文中的少量重复内容，但不改变核心需求、优先级和范围。

## 1. 项目概述

团队需要设计并开发一个金融投资组合管理应用。

投资组合可以包含以下一种或多种资产：

- 股票
- 债券
- 现金
- 其他后续确认的资产

项目的主要任务是构建一个能够保存、查询和展示投资组合内容的应用。

## 2. 技术目标

培训第一阶段的主要目标是开发一个投资组合管理 REST API。API需要能够保存和读取描述金融投资组合内容的记录。

核心功能完成后，导师可能提供进一步的增强需求。增强需求将更加开放，团队可以结合成员的技能和经验进行设计。

项目将在前端培训阶段继续开发。前端可以使用培训中学到的技术；如果希望采用其他框架或技术，需要先与导师确认。

## 3. 前端功能优先级

前端应当按照以下顺序支持用户：

1. 浏览投资组合。
2. 查看投资组合表现，最好使用图表展示。
3. 向投资组合添加资产。
4. 从投资组合删除资产。

导师将作为客户提供详细要求，团队可以根据需要安排需求沟通会议。

## 4. 范围和基本假设

- 初期不需要身份认证。
- 默认只有一个用户，不需要管理多个用户。
- 持久化存储应使用培训中学习的数据库技术。
- 应合理使用Git，尽量采用功能分支和Pull Request。
- 应提供REST API使用文档；如果培训涉及Swagger，可以使用Swagger/OpenAPI。
- 团队应保持敏捷，避免初期设计过于复杂的数据模型。

## 5. 最小可用产品（MVP）

第一版应从非常简单的数据模型开始。原文建议的最小字段包括：

```text
id
stockTicker
volume
```

结合当前项目设计，可以表示为：

```text
id
assetType
symbol
quantity
```

第一版只需要证明系统能够：

- 新增一项资产。
- 查询投资组合中的资产。
- 删除一项资产。
- 将数据持久化到数据库。

系统工作以后，再逐步增加买入价格、当前价格、购买日期、收益率等字段。

## 6. 技术启动清单

1. 创建项目结构。
2. 创建Git仓库。
3. 提交并推送项目骨架。
4. 确保所有团队成员都能访问仓库。
5. 决定第一版数据模型的最少字段。
6. 如果这些基础步骤受阻，应尽快向导师寻求帮助。

## 7. 项目管理启动清单

1. 团队共同决定工作方式，例如：
   - 两人负责后端，一人负责UI设计；
   - 或者全部成员先共同完成最小后端。
2. 建立任务列表，最好使用Trello或类似看板。
3. 可以由部分成员设计较完整的应用，其他成员先构建小型可运行示例。
4. 优先选择最小实现所需的任务。
5. 记录需要向导师确认的问题。
6. 团队共同决定初始数据模型，但必须保持敏捷。

原文特别提醒：团队最常见的问题之一，是一开始就创建过于复杂的数据模型。

## 8. 成功建议

- 从小做起，先让一个简单对象能够成功保存和读取。
- 尝试结对编程。
- 维护团队沟通和积极氛围。
- 安排固定的团队同步会议。
- 重视质量，而不是单纯追求功能数量。

## 9. 团队协作要求

- 团队应当自组织并密切合作。
- 潜在阻塞问题应及时报告给导师。
- 使用任务管理系统跟踪任务和进度。
- 所有源代码都应使用Git管理。
- 可以为前端和后端建立不同仓库，但所有仓库必须方便团队成员和导师访问。
- 仓库可以公开，也可以明确共享给导师和所有团队成员。
- 团队应定期进行进度同步。

## 10. 金融行情数据

项目可以从Yahoo Finance获取金融数据。

Java项目可以研究Yahoo Finance相关Java库；Python项目可以使用`yfinance`或直接读取Yahoo Finance历史数据。

原文还提供了一个缓存行情的示例REST API：

```text
https://c4rm9elh30.execute-api.us-east-1.amazonaws.com/default/cachedPriceData?ticker=TSLA
```

示例服务默认支持的代码包括：

```text
C
AMZN
TSLA
FB
AAPL
```

外部行情数据用于获取股票价格和历史表现；用户持仓数据仍应保存在项目自己的数据库中。

## 11. AI延伸方向

核心功能完成后，可以研究AI在投资组合管理中的应用：

- 根据风险承受能力和市场情况提出再平衡建议。
- 推荐买入、持有或卖出。
- 根据历史数据预测投资组合表现。
- 估算风险和潜在回报。
- 支持自然语言查询，例如“显示我的科技股”。
- 对金融新闻进行情感分析。
- 自动生成投资组合表现总结。
- 检测异常交易。

建议按照难度逐步尝试：

### 初级

- 基于规则提出建议。
- 使用基础统计方法识别趋势。
- 根据阈值生成提醒。

### 中级

- 使用scikit-learn进行回归、分类或聚类。
- 使用Yahoo历史数据训练模型。
- 对比预测结果与真实结果。

### 高级

- 集成大语言模型API。
- 使用LSTM或Prophet进行时间序列预测。
- 研究强化学习交易策略。

## 12. 量子计算延伸方向

量子计算可以用于研究：

- 投资组合配置优化。
- 风险与收益的约束优化。
- Monte Carlo模拟。
- Value at Risk等风险指标。
- 高维金融数据中的模式识别。

可使用模拟器而不是真实量子硬件，例如：

- IBM Qiskit
- D-Wave Ocean SDK
- Amazon Braket
- Google Cirq

一个可行的概念验证是：

1. 选择4至5项资产。
2. 准备预期收益和协方差数据。
3. 使用QAOA寻找资产组合。
4. 使用经典优化算法计算同一问题。
5. 比较结果、速度和限制。

AI和量子功能都是延伸目标，不应影响核心REST API和前端功能的交付。

## 13. 可选的高级API

如果团队实现AI或量子功能，可以考虑：

```http
GET  /portfolio/predictions
GET  /portfolio/optimize
POST /portfolio/query
GET  /portfolio/quantum-optimize
```

高级功能应当：

- 清楚标记为实验性功能。
- 显示预测置信度。
- 说明算法、数据来源和限制。
- 避免将实验结果描述为正式投资建议。

## 14. 项目展示

最终项目将向导师、经理或其他相关人员展示。展示通常为15至30分钟，具体时间由导师决定。

建议的展示顺序：

1. 介绍团队。
2. 介绍项目背景和任务。
3. 说明团队分工和开发方法。
4. 介绍技术和工具。
5. 展示数据模型。
6. 展示系统架构。
7. 进行现场演示。
8. 说明遇到的技术和协作挑战。
9. 总结经验和可以改进的地方。
10. 说明如果有更多时间会继续完成什么。
11. 进入问答环节。

所有成员都需要在最终展示中发言。

## 15. 成功标准

核心项目成功标准：

- REST API能够保存、查询和删除投资组合资产。
- 数据能够持久化。
- 用户能够通过前端浏览和管理投资组合。
- API和项目运行方式有清晰文档。
- 团队合理使用Git、分支和Pull Request。
- 项目可以稳定演示。

延伸项目成功标准：

- 能说明AI或量子计算如何应用于投资组合管理。
- 记录研究过程、问题和收获。
- 创建一个可展示的概念验证。
- 明确说明实验结果的限制和生产化所需工作。
